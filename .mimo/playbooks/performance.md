# Playbook — Performance

Гейт G5. «Быстро» = число из прогона (V6), не ощущение.

1. **Бюджет.** Зафиксировать целевой бюджет (p95/длительность/throughput) до работы.
2. **Замер ДО.** Прогнать на реалистичных объёмах (не 1 строка). Сохранить число.
3. **Найти узкое.** `EXPLAIN` на ключевом запросе; искать N+1/полные сканы (B4/B3); оценить стоимость транзакции обхода (B1) и удержание лока (B2).
4. **Изменение.** Индекс (обоснованный, T8) / запрос / батч — в scope (V8).
5. **Замер ПОСЛЕ.** То же измерение; сравнить до/после; убедиться в бюджете.
6. **Регресс.** `mvn clean verify` зелёный; функционально не сломано.
7. **Приложить числа.** Вывод бенча/EXPLAIN в отчёт.

**Горячие точки ZBPM:** перезагрузки `getVariables` за шаг (B4), poll таймеров без индекса (B3/T8), пессимистичный лок инстанса (B2).

**Анти-имитация:** «должно быть быстрее» без замера = не принято; бенч на нереалистичном объёме = не принято.
