# Playbook — Incident Response (прод/runtime)

Для прод-инцидентов и runtime-инцидентов движка (engine `incidents`).

## Прод-инцидент
1. **Стабилизировать.** Оценить влияние; при необходимости — откат (CI rollback / previous tag, [deployment](../../docs/deployment.md)).
2. **Зафиксировать факты.** Логи/трейс/время; что именно сломалось (по диску/мониторингу, не по догадке).
3. **Воспроизвести в тесте.** Перевести инцидент в падающий тест (V3) до фикса.
4. **Фикс по [bugfix](bugfix.md)** + proof-of-failure.
5. **Post-mortem.** Корень, как поймали, что добавить в тесты/гейты/память (повторяющийся дефект-паттерн).

## Runtime-инцидент движка
- Источник: `raiseIncident` (ERROR-активность + `incidents`). Токен **запаркован**, процесс не откатан (P4).
- Разбор: `incidents` → `activityId` → `bpmnElementId`/сообщение. Причина (FEEL/конверсия/воркер/модель).
- Разрешение: исправить данные/модель/код → `resolveIncident` (применяет переменные, отменяет старую ERROR-активность, ре-執 execute). Анти-double-advance уже встроен.

**Анти-имитация:** «поправил по логам» без воспроизводящего теста = не принято.
