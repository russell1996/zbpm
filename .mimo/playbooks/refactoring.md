# Playbook — Refactoring

Рефакторинг **не меняет поведение** — и это надо доказать.

1. **Сеть тестов.** Убедиться, что поведение покрыто тестами ДО рефактора (иначе сначала добавить характеризующие тесты).
2. **Цель.** Чётко: что улучшаем (читаемость/границы/дублирование) и зачем (трассировка к T*/M*). Не «ради красоты».
3. **Малые шаги.** Каждый шаг — зелёный `mvn clean verify`. Без смешивания с фичами/багфиксами (V8).
4. **Без изменения контракта** без ADR (V10). Границы модулей не нарушать (V7).
5. **Доказательство неизменности.** Те же тесты зелёные до и после; поведение идентично (при возможности — характеризующий тест на ключевой путь).
6. **Перф (если заявлен мотив).** Замер до/после (V6) — иначе «оптимизация» не засчитывается.

**Анти-имитация:** переименования/переносы, выдаваемые за результат, без снижения дублирования/улучшения границ — косметика (V4), не принимается.
