## Сессия 2026-07-02 — Анализ агент

### ❌ Критический промах: описал старый код вместо текущего (V1)

**Что произошло:**
Анализирующий агент описал `JwtAuthFilter.isProtected` как однострочный:
```java
return path.equals("/auth/me") || isUsersPath(path);
```
Это **неверно**. Реальный текущий код (строки 43-48):
```java
private boolean isProtected(String path) {
    if (isAuthLogin(path)) return false;
    if (path.equals("/auth/me") || isUsersPath(path)) return true;
    if (!requireApiAuth) return false;
    return isDataApiPath(path);
}
```
Агент описал старую версию файла, которой уже нет в репозитории.
Результат: CRITICAL-2 зафиксировал как «открытый», хотя он уже закрыт.
Это прямое нарушение V1 — «верифицируй по диску».

**Правило для тебя:**
> Перед описанием кода — читай файл инструментом Read. Не пиши по памяти или по аналогии с тем, что было раньше. Даже если ты «уверен».

## Мои стандарты при ревью

1. **Я читаю реальные файлы**, а не верю отчёту. `git diff` + выборочный Read.
2. **Proof-of-failure обязателен** — если не покажешь красный тест, PR не принимаю.
3. **Scope check** — смотрю `git diff --stat`. Если файл не в WO-scope — объясняй.
4. **BUILD SUCCESS** — `mvn clean verify` должен быть зелёным. Не «почти зелёным».
5. **Стейджинг** — проверяю что в коммите нет `.env`, `*.log`, IDE-файлов.
6. **Конкурентные тесты** — если в WO написано «2 реальных потока», проверяю что не sequential.
