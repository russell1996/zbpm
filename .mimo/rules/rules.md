# Rules — инварианты «всегда / никогда»

Нарушение любого правила = задача **НЕ ПРИНЯТА**. Правила объективны: проверяются grep/find/запуском/замером.

## Анти-имитационные правила (V1–V10) — ядро

| # | Правило | Как проверяется |
|---|---------|-----------------|
| **V1** | **Верификация по диску.** Принимается только подтверждённое grep/find/запуском. «Сделал в чате» ≠ «есть в репо». Расхождение = не принято. | Claude перечитывает диск, не отчёт |
| **V2** | **Объективная приёмка.** К задаче — механически проверяемые критерии: `grep X→0`, `тест Y зелёный`, `find Z непусто`, `замер N в бюджете`. | Критерии в work order, прогон команд |
| **V3** | **Proof-of-failure.** Зелёный тест — не доказательство, пока не показан **красным** на сломанном поведении/мутации и зелёным после фикса. Тест без assert / лог-вместо-assert — запрещён. | `git stash` фикса / мутация → тест краснеет |
| **V4** | **Запрещено:** `@Disabled`/skip, мок/in-memory вместо реального пути там где нужен реальный, ослабленные ассерты, happy-path как доказательство, косметика вместо сути, хардкод под тест. | grep на `@Disabled`, `@Ignore`, review диффа |
| **V5** | **«Код в файле» ≠ «сделано».** Фича готова, только если символ **вызывается из рабочего пути** И покрыт фальсифицируемым тестом. | grep call-site; трассировка вызова |
| **V6** | **Замеры, не оценки.** Производительность/латентность/совместимость — числом из прогона. Совместимость — против авторитетного оракула, не рукописного ожидания. | приложен вывод прогона/бенча |
| **V7** | **Границы.** Модули не импортируют internal друг друга — только через контракты. Ошибки не глотать; идемпотентность; secure-by-default. | grep import; review |
| **V8** | **Фокус.** Одна задача за раз. Нельзя делать смежное лёгкое вместо назначенного трудного. «Сделал не то» = не принято. | дифф ⊆ scope work order |
| **V9** | **Честность допустима.** «Не смог, потому что X» — принимается; задача адаптируется под ограничение. Фейк — нет. | отчёт содержит явные «НЕ СДЕЛАНО:<причина>» |
| **V10** | **Не переизобретать.** Архитектурные решения — в ADR. Отклонение = новый ADR + эскалация, не самодеятельность. | наличие ADR на структурное изменение |

## Всегда
- Первое действие итерации: `git status` + `git log` (понять состояние master/веток/незакоммиченного).
- Работать в feature-ветке; открывать PR; в master мёржит **только Claude** после гейтов.
- Conventional commits: `feat(scope):`, `fix(scope):`, `docs:`, `ci:`, `chore:`, `test:`, `refactor:`.
- Stage конкретные файлы (никогда `git add -A` вслепую).
- Каждое изменение поведения → фальсифицируемый тест + proof-of-failure.
- Числа — замерены; сравнение совместимости — против оракула (реальная Camunda/спецификация).
- Изменения трассируются к коду наблюдения (P/M/B/T/F/S/SEC) и/или цели роадмапа.
- Null-safety на публичных входах; ошибки → инцидент/исключение, не тихий drop.
- Схема БД — только через Liquibase changeset.

## Никогда
- Не пушить в master напрямую; не мёржить свой PR; не релизить/тегировать (это делает Claude).
- Не коммитить секреты/`.env`; не амендить уже запушенные коммиты; не `--no-verify`.
- Не отключать/скипать тесты ради «зелёного»; не ослаблять ассерты; не подгонять хардкод под тест.
- Не подменять реальный путь (БД/движок/сеть) моком там, где нужен реальный.
- Не делать косметику вместо сути и не выдавать happy-path за общее решение.
- Не импортировать `*.impl`/internal чужого модуля; не связывать модули в монолит.
- Не глотать исключения (`catch {}` пустой); не менять `zorrobpm-engine`/`zorrobpm-contract` без ADR/одобрения.
- Не приукрашивать отчёт. Приукрашивание = задача не принята.

## Эскалация
Уперся в невозможность / нашёл конфликт с ADR / задача требует структурного изменения → **останавливайся и
эскалируй** по [prompts/escalation.md](../prompts/escalation.md) (что, почему, варианты). Молчаливая
самодеятельность хуже честной остановки (V9/V10).
