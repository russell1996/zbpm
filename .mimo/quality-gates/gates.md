# Quality Gates (7) — объективные

Гейт проходится **командой/замером**, не «на глаз». Проваленный гейт = возврат на доработку. Владелец гейта
указывает роль, отвечающую за вердикт. В master мёржит только Claude после прохождения релевантных гейтов.

| # | Gate | Когда | Владелец |
|---|------|-------|----------|
| G1 | Architecture | до реализации структурных изменений | chief-architect |
| G2 | Design | до кодирования фичи | профильный architect |
| G3 | Implementation | по готовности кода | code-review-architect |
| G4 | Testing | вместе с кодом | test-architect |
| G5 | Performance | для перф-чувствительного | performance-architect |
| G6 | Security | для security-поверхности | security-architect |
| G7 | Release | перед merge/тегом | release-architect (вердикт Claude) |

---

## G1 — Architecture
- **Вход:** предложение структурного изменения (модуль/контракт/модель исполнения).
- **Критерии (объективно):** есть **ADR** (контекст/решение/последствия/альтернативы); не нарушены границы модулей (V7); изменение `contract`/`engine` обосновано и одобрено.
- **Проверка:** `find docs -name "ADR-*"` непусто для изменения; grep на новые cross-internal импорты = 0.
- **Выход:** одобренный ADR.

## G2 — Design
- **Вход:** дизайн фичи (контракт API, схема данных, точки в коде).
- **Критерии:** определены объективные критерии приёмки (V2); указаны затрагиваемые классы/файлы; миграции спланированы (Liquibase); обратная совместимость контракта оценена.
- **Проверка:** work order содержит измеримые acceptance + список файлов.
- **Выход:** утверждённый work order / план.

## G3 — Implementation
- **Вход:** PR с кодом.
- **Критерии:** `mvn clean verify` зелёный (10/10); дифф ⊆ scope (V8); нет проглоченных ошибок/мокнутого реального пути (V4/V7); код **вызывается из рабочего пути** (V5, показан call-site); доки/контракты обновлены.
- **Проверка:** `mvn clean verify`; `git diff` ревью; grep call-site символа.
- **Выход:** код принят к тестовому гейту.

## G4 — Testing
- **Вход:** тесты на изменённое поведение.
- **Критерии:** фальсифицируемый тест с сильным assert (V3); **proof-of-failure** показан (красный на баге → зелёный после фикса); реальный путь (engine-IT на H2 со схемой), не заглушка; нет `@Disabled`/skip (V4).
- **Проверка:** `mvn -pl <module> test -Dtest=<XIT>`; откат фикса/мутация → тест краснеет; `grep -rn "@Disabled\|@Ignore" src` = 0 (или обоснованно).
- **Выход:** тестовое покрытие подтверждено падением.

## G5 — Performance
- **Вход:** перф-чувствительное изменение (шаг обхода, запросы, таймеры, индексы).
- **Критерии:** **замер числом** (V6) до/после в бюджете; нет N+1/полных сканов на горячем пути; индексы под запрос.
- **Проверка:** приложен вывод бенча/прогона; `EXPLAIN` на ключевом запросе; сравнение до/после.
- **Выход:** числа в бюджете, приложены.

## G6 — Security
- **Вход:** изменение security-поверхности (auth, ввод, секреты, CORS, deserialization, FEEL-источник).
- **Критерии:** нет дефолтных секретов в проде (fail-fast); вход валидируется; защищённые эндпоинты возвращают 401/403 без токена; нет логирования секретов; threat учтён (SEC*).
- **Проверка:** тест 401 на защищённый путь (красный до фикса); grep дефолтных секретов; `/security-review` при необходимости.
- **Выход:** security-критерии выполнены и протестированы.

## G7 — Release
- **Вход:** ветка, готовая к merge.
- **Критерии:** все релевантные гейты G1–G6 зелёные; полный `mvn clean verify` + `npm run build` зелёные; DoD выполнен; честный отчёт приложен; CHANGELOG/версия (если релиз) — Claude.
- **Проверка:** Claude перечитывает диск, прогоняет build/test, верифицирует каждый критерий приёмки.
- **Выход:** **merge в master (только Claude)**; тег/релиз — только Claude.
