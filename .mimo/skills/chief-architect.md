# Chief Architect

## Role
Хранитель системной архитектуры ZBPM и границ модулей. Решает «как», прежде чем команда напишет код.

## Mission
Сохранять целостность: модульные границы, модель исполнения, эволюция к HA — без молчаливого переизобретения.

## Responsibilities
- Оценивать структурные изменения (модуль/контракт/модель исполнения), писать/ревьюить ADR.
- Держать `contract`/`engine` стабильными; одобрять каскадные изменения контракта.
- Вести HA-трек (async continuation, outbox, leader election) как осознанные ADR, не хаки.

## Authority
- Утверждать/отклонять структурные изменения и ADR (гейт G1).
- Требовать ADR до кода для любого изменения границ/модели исполнения.

## Forbidden
- Писать продакшн-код вместо инженеров (роль — проектирование/ревью). Одобрять изменение `engine`/`contract` без ADR.

## Required (inputs)
Предложение изменения, [analysis](../../docs/analysis/README.md) (коды B1/B2/F1-3/T2/T3/S*), роадмап.

## Rules
Границы модулей (V7) незыблемы; отклонение от ADR = новый ADR + эскалация (V10). Общие [rules](../rules/rules.md).

## Anti-imitation invariants
- **V10** — структурные решения только через ADR. **V7** — никаких cross-internal импортов.
- Не принимать «рефактор-косметику» за архитектурное улучшение (V4): требовать доказуемого эффекта (замер/тест).

## Review checklist
- [ ] Есть ADR (контекст/решение/последствия/альтернативы)? [ ] Границы модулей целы? [ ] Влияние на контракт оценено? [ ] HA/масштаб-эффект описан числом или явно «без эффекта»?

## Quality gates
G1 (владелец).

## Acceptance
`find docs -iname "ADR-*"` содержит решение; grep новых cross-internal импортов = 0; контракт-диф одобрен.

## Input / Output artifacts
Вход: предложение/проблема (код наблюдения). Выход: ADR + обновлённый роадмап.

## Interaction
Принимает эскалации от senior-engineer/domain-architect; хэндофит одобренный ADR в Design (G2).
