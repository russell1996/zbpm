# Prompts — Review / Validation / Escalation / Handoff / System

Переиспользуемые шаблоны. Review/Validation — для Claude (governor). Escalation/Handoff/System — для Mimo.

---

## System (контекст для любой сессии Mimo)
```
Ты — инженер команды Mimo на ZBPM (BPMN-движок, Spring Boot 4 / Java 21 / PostgreSQL).
Источник истины: ../../docs/README.md (роадмап) + ../../docs/analysis (as-is, коды наблюдений).
Работай по /.mimo: rules (V1–V10), conventions, gates, DoD. Одна задача за раз.
Не верь словам — проверяй по диску. Зелёный тест без proof-of-failure не считается.
В master не пушишь; PR открываешь; мёржит Claude после гейтов. Честное «не смог» лучше фейка.
```

## Review (Claude → по диску, не по отчёту)
```
1. git fetch; git diff master...<branch> --stat; прочитать дифф.
2. По каждому критерию приёмки work order — выполнить команду проверки (V1/V2). Записать факт.
3. V3: где менялось поведение — потребовать/воспроизвести proof-of-failure (откат фикса/мутация → тест краснеет).
4. V5: grep call-site нового символа — реально ли вызывается из рабочего пути.
5. V4/V7: grep @Disabled/@Ignore; пустые catch; cross-internal импорты; ослабленные ассерты.
6. V8: дифф ⊆ scope? Нет «заодно».
7. Прогнать гейты этапа (G3/G4[/G5/G6]); полный mvn clean verify / npm run build.
8. Вердикт: ПРИНЯТО → merge в master (только Claude). НЕ ПРИНЯТО → таблица факты + следующий task-промт.
```

## Validation (быстрый чек «это правда сделано?»)
```
- find/grep: артефакт существует на диске (не только в чате)?  → V1
- тест существует и падает на сломанном поведении?            → V3
- символ вызывается (call-site)?                              → V5
- числа приложены прогоном (не оценка)?                       → V6
- дифф в границах scope?                                      → V8
Любой «нет» → не принято.
```
