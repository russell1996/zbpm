# FEEL / ioMapping conformance matrix — 8.9 docs | Zeebe 8.5 live | ours

WO-OPS-30 Ф1. Поведение измерено на **живом Zeebe 8.5.0** (`camunda/zeebe:8.5.0`) и нашем движке;
дизайн/спецификация — **docs.camunda.io 8.9**. Каждая строка — один мини-процесс из
`zorrobpm-engine/src/test/resources/feel-iomapping-cases.json`; `ours` снят с реального
`RuntimeService` → handler → `ElementSupport` → outbox job payload (G-N), не с копии логики.

Колонки `ours strict` / `ours lenient`: strict — тестовый профиль (`zorrobpm.engine.io-mapping.strict-missing=true`),
lenient — текущий production default (`false`, WO-ENG-30). Live-значения — **сырой JSON** из `variablesRaw`;
JS-объект `variables` теряет точность int64 (см. `num-large-long`), поэтому для чисел 2^53+ используйте raw.

**Итог: 77 `match`, 15 `ours differs`, 2 `docs≠8.5` (94 кейса).** WO-C8-54 (2026-10-20): строки 8, 16, 19, 20, 21, 22, 27, 29, 30, 48, 49 (корень 1 Ф1) — `match` после фикса null-семантики io-mapping; +12 строк условий гейтвеев (G-Q п.3). WO-C8-56 (2026-10-19): строки 10 (`str-single`), 23 (`missing-coalesce`), 60 (`eq-only`) переизмерены — отказ на деплое вместо runtime. WO-C8-53: строки #63/#65/#70/#71/#72 — `match` после фикса. WO-C8-55 (2026-10-20, корень 3 Ф1): строки 57 (`noeq-literal`), 58 (`noeq-var`) — `match` после фикса «source без «=» — статическое значение»; +5 новых строк 85–89 (тот же корень: число, JSON-текст, пробелы, output-отказ на деплое ×2) + 3 новых строки 90–92 (MI-поля: `inputCollection`/`outputElement` без «=» → отказ на деплое, текст live-8.5) + 2 новых строки 93–94 (формы, которые консьюмер пишет ВМЕСТО отвергнутой: голая ссылка и контекст — обе `match`, обе на live-8.5). (Сводка пересчитана maintainer при слиянии веток: 45 исходных match + 2 (C8-56) + 5 (C8-53) + 2 (C8-55) + 5 (C8-55, новые кейсы) + 3 (C8-55, MI-поля) + 2 (C8-55, формы замены).)

Вердикты: `match` — поведение совпадает (с оговоркой в примечании, если она есть);
`docs≠8.5` — 8.9-документация расходится с живым 8.5, дефолт — живой 8.5;
`ours differs` — расхождение с живым 8.5 → кандидат в баг-WO. «Цель дизайна» (есть в 8.9, нет в 8.5)
не реализуется в Ф1 без решения владельца.

## Вложенный target: класс правил (корень 4 Ф1, WO-C8-58)

Правило live 8.5: target с точкой создаёт **вложенный контекст** (не плоский ключ с точкой в
имени). Замеры — на живом Zeebe 8.5.0 (`docs/analysis/c8-oracle/feel-iomapping-static-nested.js`,
пробы `tgt-nested`, `tgt-nested-deep`, `tgt-nested-parent-string`, `tgt-nested-parent-ctx`,

движке (те же кейсы в `feel-iomapping-cases.json`, те же live-8.5 ожидания в харнессе
`FeelIoMappingConformanceIntegrationTests`).

Четыре правила класса: (1) вложенность по всем сегментам; (2) родитель **ЗАМЕНЯЕТСЯ** (значение
родителя из внешнего скоупа не сливается — оно затеняется скоупом элемента); (3) два маппинга в
ОДИН родителя объединяются; (4) то же — на стороне output (там запись идёт в скоуп родителя).

## Примечания и ограничения

- `target-nested` (строка 61, корень 4 Ф1) — **ПОЧИНЕН в WO-C8-58 (2026-10-20)**. Решение maintainer
  от 2026-10-20 (вариант 2 эскалации WO-C8-55): отдельная WO «nested target + контракт
  коннектора». Прод-совместимость обеспечена порядком «сначала воркеры»: `HttpConnectorWorker`
  и `CamundaHttpJsonWorker` читают ОБЕ формы (плоский ключ `http.url` И вложенный путь
  `http`→`url`), приоритет — вложенная форма, плоский ключ — fallback; сохранённое состояние
  живых инстансов (`connCamunda v1`, `connNative v1` — плоские `http.*` в таблице `variables`)
  продолжает работать без миграции данных. Класс правил измерен на живом 8.5.0 и закрыт
  полностью: строки 61 и 95–100 — `match`.
- Правило «source без «=» — статическое значение» НЕ переносится на MI-поля
  (`inputCollection`/`inputElement`/`outputElement`) — там своя семантика, и live 8.5 отказывает
  такой модели НА ДЕПЛОЕ («Expected expression but found static value 'probeId'…»), а не доставляет
  литерал. Замер: тот же оракул, сценарии `mi-outputelement-noeq`, `mi-inputcollection-noeq`.
  Это ровно то, чего требует WO («НЕ переноси правило «статика» туда, куда Zeebe его не применяет»).
  **WO-C8-55 (2026-10-20, решение maintainer) реализовал именно ОТКАЗ, а не доставку литерала:**
  `inputCollection`/`outputElement` без «=» → 400 `INVALID_FEEL_EXPRESSION` на деплое, текст
  live-8.5 (строки 90–92). `inputElement`/`outputCollection` — имена, не выражения: не
  отвергаются (живой 8.5, проба `mi-inputelement-plain` → `completed`; в нашем корпусе это
  покрыто всеми MI-кейсами — `mi-basic`/`mi-sequential`/`mi-empty-output` пишут их без «=»).
- Пустой source (`empty-source`, строка 59) — НЕ менялся: он и раньше шёл по legacy-ветке
  (пустая строка), а не по статике; live 8.5 отказывает ему на деплое (строка остаётся `docs≠8.5`).

- `path-quoted` oracle отработал как `cancelled/noWorkJob`; Operate API не включён, поэтому сообщения инцидента в oracle-файле нет. Наш strict даёт `[INVALID_TYPE]`, lenient — `""`; обе стороны считают форму невалидной, различие — в фазе/диагностике. Перепроверено 2026-10-19 на живом 8.5.0 (`docs/analysis/c8-oracle`, `node feel-iomapping.js path-quoted`): деплой проходит, инстанс стартует, на runtime — `cancelled/noWorkJob` (как в F1), backtick/get-value формы — `completed` с `r="V"` → **deploy-отсечение для этой формы НЕ нужно** (WO-C8-56, item 4); расхождение остаётся только в runtime-оценке (другой корень).
- `datetime-literal` / `string-now` — осознанно принятое расхождение WO-ENG-33 (`ElementSupport.toProcessVariable` → ISO-offset; слой `string(now())` с `@Zone` не чинится, паритет с Camunda).
- `num-div` — одинаковое IEEE-754 значение на проводе; канонический Decimal отличается (наш DOUBLE хранит 34 знака, live печатает 16). Классифицирован как `match` с оговоркой.
- `num-large-long` — сравнение только по `variablesRaw`; JS `variables.r` равен `9007199254740992` из-за `JSON.parse`, это дефект измерения, а не поведение Zeebe.
- `empty-source` — 8.9 говорит «optional source → null», живой 8.5 отвергает деплой; наше поведение (runtime-reject) ближе к 8.5 по факту отказа, но не по фазе. Это цель дизайна/решение владельца, не баг-фикс Ф1.
- `eq-only` — 8.9 требует выражение после `=`, живой 8.5 считает `=` статической строкой (completes с `r="="`); наше поведение следует 8.9 (отказ) — после WO-C8-56 (2026-10-19) отказ на деплое (400 INVALID_FEEL_EXPRESSION), раньше был в runtime.
- Все `ours differs` — кандидаты в отдельные баг-WO; в Ф1 ядро не правилось (V7/план кампании). Исключение, снятое решением владельца: `num-above-long` — **by design, ours differs** (решение maintainer 2026-10-21, WO-AUDIT-17 п.3; тихое переполнение Zeebe 8.5 воспроизводить нельзя — см. примечание ниже).
- **Условия гейтвеев (WO-C8-54) — отдельный корень, НЕ починен в этом WO.** Наш путь условий
  (`FlowNavigator.processFlow:489` → `scriptService.evaluateScript`) оценивает условие FEEL-**unary-test**
  движком (`ScriptEngineConfiguration.feelScriptEngine` = `FeelUnaryTestsScriptEngineFactory`), а не полным
  FEEL-движком. Замер (живой 8.5 против нашего движка, одинаковые выражения) показал ИНВЕРСИЮ:
  | выражение | наш unary-test | наш полный FEEL | live 8.5 |
  |---|---|---|---|
  | `true` | `false` | `true` | условие берётся (инцидента нет) |
  | `nope` (переменной нет) | `true` | `null` | инцидент |
  | `1 < "2"` (несравнимые) | `true` | `null` | инцидент |
  | `round(2.5)` (нет функции) | `true` | `null` | инцидент |
  | `null` | `true` | `null` | инцидент |
  | `nope = "x"` | `false` | `false` | default-поток (совпадает) |
  То есть у нас условие, которое не даёт значения, ВЕТКУ БЕРЁТ (в Zeebe — инцидент), а `=true` — НЕ берёт
  (в Zeebe — берёт). Это ПРЕ-существующий дефект маршрутизации (не следствие фикса C8-54: путь условий
  фикс не трогает) — V7, в этот WO не входит; требует отдельного WO (правка меняет маршрутизацию
  развёрнутых определений — эскалация владельцу). Строки 73–84 матрицы — его доказательства.
- **`num-above-long` (корень 7 Ф1) — РЕШЕНО 2026-10-21 (maintainer): «by design, ours differs» (WO-AUDIT-17 п.3).**
  Live 8.5: `9223372036854775808` → `-9223372036854775808` (усечение long, как
  `longValue()`), 8.9 docs — BigDecimal без предела. Наш движок: `ArithmeticException: Overflow` →
  `EngineException` (явный отказ, WO-ENG-21 N10 — тихое усечение запрещено осознанно).
  **Основание решения:** тихое целочисленное переполнение — дефект Zeebe 8.5 (8.9-документация обещает
  BigDecimal, т.е. 8.5 ведёт себя вопреки собственной спецификации); воспроизводить его значило бы
  сознательно вносить порчу данных. Альтернатива «хранить длинные целые как JSON-число (BigDecimal)» —
  отдельное решение по модели переменных, в этот WO не входит. Строка матрицы №5 помечена «by design»
  (вердикт `ours differs` остаётся: расхождение с живым 8.5 зафиксировано, но оно НЕ дефект).
