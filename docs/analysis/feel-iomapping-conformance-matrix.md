# FEEL / ioMapping conformance matrix — 8.9 docs | Zeebe 8.5 live | ours

WO-OPS-30 Ф1. Поведение измерено на **живом Zeebe 8.5.0** (`camunda/zeebe:8.5.0`) и нашем движке;
дизайн/спецификация — **docs.camunda.io 8.9**. Каждая строка — один мини-процесс из
`zorrobpm-engine/src/test/resources/feel-iomapping-cases.json`; `ours` снят с реального
`RuntimeService` → handler → `ElementSupport` → outbox job payload (G-N), не с копии логики.

Колонки `ours strict` / `ours lenient`: strict — тестовый профиль (`zorrobpm.engine.io-mapping.strict-missing=true`),
lenient — текущий production default (`false`, WO-ENG-30). Live-значения — **сырой JSON** из `variablesRaw`;
JS-объект `variables` теряет точность int64 (см. `num-large-long`), поэтому для чисел 2^53+ используйте raw.

**Итог: 47 `match`, 23 `ours differs`, 2 `docs≠8.5` (72 кейса).** Строки 10 (`str-single`), 23 (`missing-coalesce`), 60 (`eq-only`) переизмерены 2026-10-19 после WO-C8-56: отказ на деплое вместо runtime (остальные 69 строк без изменений — сверено построчно с `target/feel-iomapping-observed.json`).

Вердикты: `match` — поведение совпадает (с оговоркой в примечании, если она есть);
`docs≠8.5` — 8.9-документация расходится с живым 8.5, дефолт — живой 8.5;
`ours differs` — расхождение с живым 8.5 → кандидат в баг-WO. «Цель дизайна» (есть в 8.9, нет в 8.5)
не реализуется в Ф1 без решения владельца.

## Примечания и ограничения

- `path-quoted` oracle отработал как `cancelled/noWorkJob`; Operate API не включён, поэтому сообщения инцидента в oracle-файле нет. Наш strict даёт `[INVALID_TYPE]`, lenient — `""`; обе стороны считают форму невалидной, различие — в фазе/диагностике. Перепроверено 2026-10-19 на живом 8.5.0 (`docs/analysis/c8-oracle`, `node feel-iomapping.js path-quoted`): деплой проходит, инстанс стартует, на runtime — `cancelled/noWorkJob` (как в F1), backtick/get-value формы — `completed` с `r="V"` → **deploy-отсечение для этой формы НЕ нужно** (WO-C8-56, item 4); расхождение остаётся только в runtime-оценке (другой корень).
- `datetime-literal` / `string-now` — осознанно принятое расхождение WO-ENG-33 (`ElementSupport.toProcessVariable` → ISO-offset; слой `string(now())` с `@Zone` не чинится, паритет с Camunda).
- `num-div` — одинаковое IEEE-754 значение на проводе; канонический Decimal отличается (наш DOUBLE хранит 34 знака, live печатает 16). Классифицирован как `match` с оговоркой.
- `num-large-long` — сравнение только по `variablesRaw`; JS `variables.r` равен `9007199254740992` из-за `JSON.parse`, это дефект измерения, а не поведение Zeebe.
- `empty-source` — 8.9 говорит «optional source → null», живой 8.5 отвергает деплой; наше поведение (runtime-reject) ближе к 8.5 по факту отказа, но не по фазе. Это цель дизайна/решение владельца, не баг-фикс Ф1.
- `eq-only` — 8.9 требует выражение после `=`, живой 8.5 считает `=` статической строкой (completes с `r="="`); наше поведение следует 8.9 (отказ) — после WO-C8-56 (2026-10-19) отказ на деплое (400 INVALID_FEEL_EXPRESSION), раньше был в runtime.
- Все `ours differs` — кандидаты в отдельные баг-WO; в Ф1 ядро не правилось (V7/план кампании).
